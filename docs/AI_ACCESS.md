# AI 接入：安全、隐私与排错

> 适用版本：StrategyGameArcades 静态站。功能状态以本文件与仓库代码为准。

## 1. 总体边界

本站是**纯静态网站**：没有自建后端、没有账号系统、没有服务端数据库，也没有转发 AI 请求的代理。

- 浏览器内算法与 JavaScript 代码策略：完全在用户设备上执行。
- 云端大模型：浏览器直连用户填写的服务商，BYOK（Bring Your Own Key）。
- localhost 服务：浏览器直连用户本机地址。
- 模型文件（JSON / ONNX）：本机读取，不上传（**当前版本尚未开放导入**，原因见 §7）。
- 开发者不在构建产物中携带任何私有 API Key；`VITE_*` 变量会进入产物，绝不能用于放密钥。

在线静态站仍然需要你信任**实际部署的这份代码**。建议核对页面底部的构建时间与 Git 提交，
或按 §8 在本机自行构建。

## 2. 一次决策会发送什么

所有 AI 席位都实现同一个 `PlayerController`：

```ts
decide({ playerId, observation, legalActions, turn, signal }) -> Promise<Action>
```

因此不论哪种接入方式，一次请求只包含：

- 游戏 ID / 名称与简短规则摘要（云端大模型）；
- 当前玩家可见的 `Observation`（全部七款游戏都是完全信息博弈，不含隐藏信息）；
- 当前合法动作列表 `legalActions`；
- 回合数、席位 ID。

不包含：账号、设备指纹、浏览历史、对局历史、真实姓名、其它游戏数据。
真人席位名称只保存在浏览器本地，不会进入模型请求。

### 数据去向

| 接入方式 | 请求路径 | 数据到达方 |
| --- | --- | --- |
| 内置算法 | 无网络 | 仅本机浏览器 |
| JavaScript 策略 | QuickJS Worker | 仅本机浏览器 |
| 云端大模型 BYOK | 浏览器 `fetch` | 用户填写的服务商 |
| localhost 大模型 | 浏览器 `fetch` | 用户本机的服务 |
| 自定义 `/decide` | 浏览器 `fetch` | 用户本机的服务 |

## 3. API Key 的存放位置

对局配置（localStorage `table.match.<gameId>`）**只保存凭据 id**，不保存 Key。

- 默认：Key 只放在运行时内存，刷新/关闭页面即消失。
- 可选「记住 Key」：显式勾选后写入 localStorage（`table.ai.credentials.v1`）。
- 「记住」是**明文保存**，没有任何加密收益；同源脚本（包括被 XSS 注入的第三方脚本）都能读取。
- 设置页提供「清空全部 AI 凭据」；席位配置里提供显示/隐藏（当前输入）、更换、删除。
- 已保存的 Key 不会回填到输入框，避免把明文再次渲染进 DOM。
- Key 不会写入错误信息、日志、URL 或遥测；错误详情只保留服务端返回体的前 200 字符。

如果清空凭据，引用它的 AI 席位会在行动时报错，并提示回配置页重新填写；
**不会**静默降级成随机动作或内置算法。

## 4. 连接测试与诊断

「测试连接」会发送一次**真实的小请求**：云端/本地模型必须返回一个能通过游戏 schema
且属于 `legalActions` 的动作；`/decide` 服务同理。只有真实推理成功才会显示通过。

失败按原因分类显示，而不是统一「连接失败」：

- URL 格式错误、使用了公网 http；
- 服务不可达 / CORS 未放行 / 浏览器阻止本地网络访问；
- 401 认证失败、403 拒绝访问、404 端点或模型不存在、429 额度限制、5xx；
- 超时；
- 响应结构不符；
- 模型返回了非法动作。

配置指纹（包含策略源码）变化后，旧测试结果立即失效，必须先重新测试才能开局。

## 5. localhost / CORS 排查

本项目不会引导你关闭浏览器安全策略，也不建议使用
`Access-Control-Allow-Origin: *`。CORS 白名单不是身份认证。

1. 确认服务只监听 `127.0.0.1`，不要监听 `0.0.0.0`。
2. 在服务端 CORS 配置中**只放行本站 Origin**：
   - 开发：`http://localhost:5173`
   - 部署：你的实际站点 Origin（含协议与端口）
3. 允许的方法至少包含 `POST, OPTIONS`，请求头包含
   `Content-Type, Authorization`。
4. 浏览器可能对 localhost/私有网络请求施加额外限制（Private Network Access /
   Local Network Access）。不同浏览器行为不同，出现「无法连接」时先看 DevTools 的
   Network / Console，再检查服务日志。
5. 如果服务仍然无法安全连接，请使用它自己的 CORS 配置解决，不要试图让本站绕过。

常见表现：

| 现象 | 可能原因 |
| --- | --- |
| 请求根本没有出现在服务日志 | 预检被拒、浏览器阻止私有网络访问、服务未监听 |
| 日志有 OPTIONS 但无 POST | CORS 未允许 `POST` 或 `Authorization` 头 |
| 401 / 403 | 令牌错误、Origin 白名单不含本站 |
| 404 | 路径不是 `/decide`，或 Base URL 前缀不对 |
| 429 | 本地服务限流 |

### CC Switch 等兼容代理

本项目**不假设**任何代理软件的具体版本、UI 选项或接口形状。它只做两件事：

- 用用户填写的 Base URL 调用 OpenAI 兼容 `POST /chat/completions`；
- 用用户填写的完整 URL 调用自定义 `/decide`。

如果某个代理版本提供上述接口，并且允许本站 Origin 的 CORS，就可以尝试连接；
是否可行以实际版本、浏览器 DevTools 与服务日志为准。没有经过验证，本项目不会声称
它一定支持浏览器跨域或某个 CORS 开关。

## 6. 云端 BYOK 的现实限制

- 是否支持浏览器跨域由**服务商**决定，本站不能承诺所有服务商都能直连。
- Anthropic Messages API 需要 `anthropic-dangerous-direct-browser-access` 头，并依赖其
  CORS 支持；被拒绝时会显示 403 或网络错误。
- 浏览器直连会把 Key 暴露在页面脚本环境中；这是 BYOK 的固有代价。
- 不做模型列表自动发现，用户自行填写 Base URL 与模型 ID。
- 不把 `provider` 写死成少数厂商：OpenAI 兼容协议和 Anthropic 协议之外的私有接口不猜测。

## 7. 小模型 / 模型文件状态

当前版本**没有**开放 JSON 权重与 ONNX 导入 UI。原因不是「做不了」，而是不做虚假能力：

- 模型权重不等于推理协议。特征顺序、归一化、玩家视角、动作索引必须与训练阶段完全一致；
  没有可验证的训练/导出协议时，导入任意权重只会得到看似成功、实际乱走的席位。
- ONNX 需要明确的输入编码器、输出解码器、形状/NaN 校验与动作映射；任意 ONNX 不等于
  棋类策略模型。

预留方向：版本化 manifest（游戏 ID、规则版本、特征编码器 ID、动作索引协议、权重/模型文件
校验和），由游戏自己提供编码器实现。WASM 策略模块同样不会被视为可信代码，必须限制
imports、内存、执行时间与宿主权限。在这些协议落地前，代码策略（JavaScript）是唯一
可安全导入的「用户逻辑」。

## 8. 完全本地部署

```powershell
pnpm install
pnpm build
pnpm preview
```

离线使用内置算法 / 人类对局不需要任何网络；localhost 模型需要本机服务运行。
页面底部的构建信息可用于核对版本。发布到静态托管时，只上传 `dist/`，不要上传任何
`.env` 或带 Key 的文件。

## 9. 残余风险

- localStorage 中的 Key 可被同源 XSS 读取；站点自身与第三方脚本的供应链安全无法由本文件保证。
- Worker + QuickJS 降低风险，但**Worker 不是完整安全沙箱**；安全性来自不向解释器暴露
  DOM、网络、存储、宿主 API，以及资源限制与超时终止。
- 用户脚本仍在用户自己的浏览器里运行；恶意策略最多消耗本机资源，不能读取本站密钥。
- 浏览器与服务商之间的 TLS、CORS、网络策略不由本站控制。
- 本机服务后端的权限、日志与数据保存策略由用户自己负责。
